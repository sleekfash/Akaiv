# Source-to-target mapping — PROVISIONAL

2026-10-14. Based on source migrations, not a deployed database inspection. Human approval is mandatory for ambiguous judicial values.

| Source | Target | Rule / unresolved item |
|---|---|---|
| Source system + documents.id | provenance legacy system/document ID | Preserve as explicit provenance; current importer only preserves batch/item/path/hash. Extend manifest/provenance before live migration. |
| documents.name | documents.friendly_name | Keep source name; do not treat filename as authoritative case title. |
| documents.file | import_items.source_path → immutable storage_path | Resolve within read-only root; preserve original relative path/hash; storage keys generated by FileIngestion. |
| documents.user_id / created_by | organization + existing authorized owner/actor | Owner-approved mapping, not synthetic accounts or inferred folder identity. Source text creator is provenance, not a trusted target user ID. |
| documents.folder_id / folder text | folder hierarchy / source provenance | Reconcile referenced IDs with folders; current file-only importer does not recreate relationships. |
| folders.active; document Available/Deleted; trash areas | reconciliation disposition | Deleted/inactive/unknown excluded from active migration pending owner review; no automatic restoration/publication. Current discoverer does not enforce these dispositions. |
| Verified case title / suit / subject | cases.title/suit_number/subject_matter | No dedicated fields in inspected legacy migration. Authorized manual mapping required; unknown remains flagged, not invented. |
| Court/division/jurisdiction | case scope + organization | Judicial owner establishes identity/uniqueness; org-only normalization is not sufficient evidence. |
| Verified delivery date | documents.date_delivered | ISO YYYY-MM-DD after ambiguity review; created_at/filename timestamps are not delivery dates. |
| Approved document category | judicial_document_type | judgment/ruling/order/case_file/transcript; current import validator lacks transcript. No autonomous classification. |
| folio_number / description | folio_number / description | Preserve only approved metadata; confidential text stays restricted. |
| Session date / presiding officer | case_proceedings | Manual authoritative mapping; current per-case/day uniqueness needs multiple-session policy review. |
| Sealed/confidential status | cases.is_sealed + explicit grants | Must be supplied/approved; absent source flag never implies public/unrestricted content. |
| File bytes | checksum, size, MIME, immutable revision | Original preserved; malware scan queued; import remains draft until distinct review. |

Current accepted manifest shape is an object keyed by source-relative path, with case_id, friendly_name, judicial_document_type and date_delivered. It is not a complete relational migration specification. Keep a restricted sidecar for original IDs/ownership/seal decisions until those fields have approved supported persistence. Do not publish real manifests here.
